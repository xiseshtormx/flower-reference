# Рабочая версия «Референс цветочного»

Сайт, база и панель работают в одном проекте: Astro + React + Node.js + SQLite.
Дизайн, шапка, ботанические рисунки и анимация hero сохранены.

## 1. Перенос файлов

Остановите старый сервер. Распакуйте `flower-working-v1.zip` и перенесите его содержимое в папку проекта с заменой файлов. В архиве сразу находятся `src`, `public`, `scripts`, `package.json` и остальные файлы проекта.

**Важно:** сохраняйте имеющиеся `.env` и папку `storage`, если они уже появились. В архиве их нет. В них находятся ваш доступ, база и фотографии.

Старые архивы правок hero/подвала поверх этой версии применять не нужно: в ней уже есть принятый дизайн и изменения для работы с базой.

## 2. Установка

Откройте PowerShell именно в папке цветочного проекта:

```powershell
Set-Location "C:\Users\XiseShtormX\Desktop\Работа\flower-reference"
node --version
npm install --registry=https://registry.npmjs.org/ --fetch-retries=0 --fetch-timeout=30000 --no-audit --no-fund
```

Нужен Node.js **24.13 или новее**. Если папку назвали иначе, укажите её настоящий путь. Устанавливаем только новые зависимости; вручную менять старые файлы не требуется.

На некоторых версиях Node 24 может появиться `ExperimentalWarning` от встроенного SQLite. Это предупреждение о модуле, а не ошибка сохранения заявки.

## 3. Создание доступа

```powershell
npm run setup
```

Введите логин латиницей и пароль от 12 символов. Пароль вводится скрыто; его нужно повторить. Команда создаст `.env` с хешем пароля и подготовит базу с восемью демонстрационными букетами.

Встроенного общего пароля нет. Чтобы сменить или восстановить пароль, остановите сервер и снова выполните `npm run setup`. Товары и заявки сохраняются, старые сессии входа завершаются.

## 4. Запуск

```powershell
npm run dev
```

- Сайт: [http://localhost:4321/](http://localhost:4321/)
- Панель: [http://localhost:4321/admin](http://localhost:4321/admin)

Если порт занят, Astro покажет другой адрес. Откройте именно адрес из терминала.

В обычном режиме сервер работает, пока открыт терминал. Остановка — `Ctrl+C`.
Если Astro запустил фоновый сервер, остановить его можно командой:

```powershell
npm run dev -- stop
```

## 5. Первая проверка

1. В панели откройте «Букеты» и измените цену размера M.
2. Обновите сайт: новая цена появится без сборки.
3. Добавьте новый букет. Заполните описание и состав, загрузите фото, включите «Показать на сайте».
4. Откройте новую карточку из каталога — она существует сразу.
5. Добавьте букет в корзину. Для первого теста выберите дату через два дня и любой доступный интервал.
6. Укажите тестовое имя и телефон, например `+7 999 123-45-67`, и подтвердите тестовый режим.
7. Нажмите «Отправить заявку». Получите номер `FL-…`.
8. В панели «Заявки» откройте её, подтвердите сумму и переведите в работу.
9. Проверьте индивидуальную форму на главной: бюджет, дата, пожелания и телефон либо Telegram тоже сохраняются.

При перезапуске сервера всё сохранится. Если скрыть товар, он пропадёт из публичного каталога. В старой корзине будет предложение удалить недоступную позицию. Содержимое уже оформленных заказов останется прежним.

## 6. Как пользоваться панелью

### Букеты

- Название, короткое и полное описание, состав.
- Категория и оттенок для существующих фильтров.
- Цены и описание объёма S/M/L.
- До шести фотографий; первую можно сделать обложкой. Изображения оптимизируются в WebP, метаданные удаляются.
- Размер на фото и кадрирование.
- Доступность: в наличии, под заказ, временно отсутствует.
- Время подготовки в днях.
- Порядок показа, небольшая метка и публикация/скрытие.

Адрес страницы после создания не меняется. Букет можно скрыть, сохранив историю заказов.

### Заявки

Два типа: товары из каталога и индивидуальный букет.

Внутри заявки: дата, контакты, получатель, адрес/самовывоз, комментарий, снимок состава и цен на момент отправки, согласованная сумма и история изменений.

Этапы: новый → подтверждён → в работе → в доставке → завершён. Для самовывоза из работы можно сразу завершить. Отмена требует причины. Завершённые и отменённые заявки доступны для просмотра.

Индивидуальную заявку подтверждают после согласования состава и суммы. Бюджет клиента не становится ценой автоматически.

Смена цены в каталоге не меняет сумму старого заказа. Изменение согласованной суммы нужно описать в комментарии. Если карточку изменили в другой вкладке, панель попросит открыть её заново вместо перезаписи чужих изменений.

### Настройки

- Контакты мастерской и адрес самовывоза.
- Включение доставки и самовывоза, стоимость доставки.
- Букет для hero.
- Рабочие дни, закрытые даты и интервалы получения.
- Час окончания приёма на сегодня и часы подготовки день в день.
- Горизонт заказа и дневной лимит.
- Цены, названия и доступность открытки/вазы.

Часы указаны по Перми, UTC+5 (`Asia/Yekaterinburg`). Букет «под заказ» требует минимум один день подготовки. Закрытые дни, прошедшие интервалы и подготовка учитываются на сервере.

Лимит относится к заказам: заявка из каталога занимает место сразу; индивидуальная — после подтверждения. Отмена освобождает место. Это не учёт стеблей на складе. Для заказа больше 24 букетов форму нужно согласовать с мастерской напрямую.

## 7. Учебный и рабочий режим

По умолчанию включён **учебный режим**. Формы действительно записывают заявки, но помечают их тестовыми. Сайт предупреждает посетителя, что цветы не доставляются и деньги не списываются. Используйте тестовые контакты.

В настройках можно выключить учебный режим после заполнения контактов мастерской и адреса самовывоза, если он включён. Тогда интерфейс показывает обычный приём заявок с подтверждением флористом.

Онлайн-оплата, покупательские аккаунты, автоматический склад и внешняя CRM в этот этап не входят. Страница «О данных заявки» описывает работу форм; перед запуском настоящего магазина её нужно адаптировать под владельца и его условия.

`noindex` оставлен: публичную индексацию настроим при подготовке к публикации.

## 8. Необязательные уведомления Telegram

Для работы сайта Telegram не требуется. В панели доступны все заявки.

Если нужны уведомления:

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите токен.
2. Напишите этому боту `/start` со своего аккаунта либо добавьте его в выбранный чат.
3. Узнайте ID нужного чата. Можно локально запросить `getUpdates`, подставив токен только у себя:

```powershell
$flowerBotToken = Read-Host "Токен бота"
Invoke-RestMethod -Uri ("https://api.telegram.org/bot" + $flowerBotToken + "/getUpdates") | ConvertTo-Json -Depth 12
Remove-Variable flowerBotToken
```

Нужное значение находится в `result → message → chat → id`. Не отправляйте токен и полный ответ в общие чаты.

4. В `.env` добавьте две строки:

```dotenv
FLOWER_TELEGRAM_BOT_TOKEN=ваш_токен
FLOWER_TELEGRAM_CHAT_ID=ваш_id_чата
```

5. Перезапустите сервер и отправьте тестовую заявку.

Уведомление содержит номер, тип, дату и сумму/бюджет. Телефоны и адреса остаются в панели. Сначала заявка сохраняется в базе, затем отправляется сообщение.

Если Telegram недоступен, запись не теряется. Очередь делает до пяти попыток с задержками при следующих обращениях к заявкам/панели. Отдельного фонового работника пока нет. В карточке заявки можно повторно поставить уведомление в очередь.

## 9. Хранение и резервная копия

Данные находятся в `storage/flower.sqlite`, фотографии — в `storage/uploads/`.
Это серверное хранение; очистка браузера не удаляет заказы.

```powershell
npm run backup
```

Команда создаёт согласованную копию базы и фотографий в `storage/backups/…`. Для восстановления: остановить сервер, переименовать текущую папку `storage` в `storage-before-restore`, создать новую пустую `storage`, скопировать туда только `flower.sqlite` и `uploads` из нужной копии, запустить сервер. Старую папку сохраняйте до проверки восстановления. Файлы `flower.sqlite-wal` и `flower.sqlite-shm` из старой базы переносить вместе с восстановленной копией не нужно.

`.env` храните отдельно и приватно: в резервную копию товаров он не включается. Данные, доступы и `storage` исключены из Git и итогового архива проекта.

## 10. Сборка и проверка

```powershell
npm run check
npm test
npm run build
npm run test:integration
npm run start
```

`start` запускает собранную версию по [http://localhost:4321](http://localhost:4321), если `PORT` не изменён. Сначала остановите dev-сервер.

Интеграционные проверки используют отдельную временную базу и отдельный порт. Ваш ассортимент и заявки они не меняют, реальные Telegram-сообщения не отправляют.

## 11. Что нужно для будущей ссылки

Текущей версии нужен **Node-сервер с постоянным диском** для SQLite и фотографий. Площадку пока не выбирали и сайт не публиковали.

GitHub может хранить код. Статический GitHub Pages сам по себе не запускает этот сервер. Для размещения на функциях с временным диском сначала перенесём базу и фотографии во внешнее постоянное хранилище.

При выбранном размещении настроим HTTPS, постоянный диск, резервные копии, домен и точный `FLOWER_PUBLIC_ORIGIN`. В текущем запуске сервер доступен локально.
